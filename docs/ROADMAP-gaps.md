## กลุ่ม A — API มีอยู่แต่ไม่มีใครเรียก (ช่องว่างที่คุ้มที่สุด)

ตรวจด้วยการ grep หา caller ของแต่ละ endpoint แล้ว พบว่า endpoint เหล่านี้ **ไม่มี UI หรือ
โค้ดฝั่ง client เรียกใช้เลย** ฟีเจอร์ถูกเขียนและมี guard/security ครบแล้ว เหลือแค่ต่อหน้าจอ

| # | Endpoint | สถานะ | รายละเอียด |
|---|---|---|---|
| A1 | `POST /api/bookings/recurring` | **ไม่มี caller** | จองแบบสัปดาห์ละครั้งได้สูงสุด 8 ครั้งในทรานแซกชันเดียว, validate ทุก slot กับตารางครู — พร้อมแล้วแค่ไม่มีปุ่ม |
| A2 | `GET /api/referrals` + `POST /api/referrals/claim` | **ไม่มี caller** | มี referral code + reward status ครบ แต่ผู้ใช้ไม่มีทางเห็นหรือใช้โค้ดแนะนำ |
| A3 | `GET /api/admin/ops-snapshot` | ✅ **เสร็จแล้ว** | การ์ด "คิวงานที่ต้องติดตาม" บน `/admin/dashboard` พร้อมระดับความเร่งด่วน 6 คิว + ลิงก์ไปหน้าที่เกี่ยวข้อง — ใช้ `src/lib/admin/ops-queues.ts` ตัวเดียวกับ API และ UAT ขั้น 10 |
| A4 | `GET /api/coupons/mine` | มีแต่เรียกจาก server | หน้า payments เรียก `ensureFirstBookingCoupon` ตรงแทน → route นี้ยังไม่มีทางเข้า |

> **ข้อสังเกต:** A1 เป็นตัวที่กระทบผู้ใช้มากที่สุด — ผู้ปกครองที่เรียนต่อเนื่องต้องกดจองทีละครั้ง

## กลุ่ม B — ช่องว่างด้านความปลอดภัย / สถาปัตยกรรม

| # | รายการ | เหตุผล |
|---|---|---|
| B1 | **Rate limiter เป็น in-memory ต่อ instance** | พอ scale หลาย instance แล้วผู้ใช้คนเดียวหลุด limit ได้เรื่อย ๆ — ย้ายไป Firestore/Redis ก่อนขึ้น production จริง |
| B2 | **Stripe webhook ยังเป็น mock-first** | README ระบุชัดว่า live transfer ยังต้องทำเป็น change แยก — ควรมี checklist ก่อนปลดล็อกเงินจริง |
| B3 | **ยังไม่มี idempotency key ระดับ request** | ปัจจุบันกันซ้ำด้วย status check ฝั่ง Firestore เป็นส่วนใหญ่ ยังไม่มี key กัน retry ซ้ำจาก mobile |
| B4 | **Audit log ของแอดมินไม่ครอบคลุมทุก action** | มี `logEvent` แล้ว แต่การปรับยอดวอลเล็ต (`/admin/parents/[id]`) ยังควรบันทึกผู้ปฏิบัติการ+เหตุผล |

## กลุ่ม C — ช่องว่างด้านผู้ใช้ / ประสบการณ์ใช้งาน

| # | รายการ | หมายเหตุ |
|---|---|---|
| C1 | **รายการที่ถูกตัดหน้า N ไม่มีปุ่ม "ดูเพิ่มเติม"** | หลายหน้า `.limit(N)` แล้วจบเงียบ ๆ ผู้ใช้ไม่รู้ว่ามีของเพิ่ม |
| C2 | **หน้าแดชบอร์ด "คิวงานของฉัน" สำหรับแอดมิน** | ✅ เสร็จแล้ว — ดู A3 |
| C3 | **รายงานภาษีประจำปีของครูเป็น PDF** | มีหน้า tax-certificate/tax-document อยู่แล้วแต่เป็น HTML — ครูต้องพิมพ์เอง |
| C4 | **ผู้ปกครองไม่มีหน้าสรุปแพ็กเกจที่ใช้อยู่** | มีซื้อ/จองต่อ แต่ไม่เห็นว่าตัวเองเหลือเครดิตกี่ครั้งรวมทุกแพ็กเกจ |
| C5 | **`/notifications` ใช้ร่วมทั้ง 3 role** | ทำงานถูกต้อง แต่ teacher/admin ไม่มีหน้า setting การแจ้งเตือน |
